# Bloom 리서치 통합 보고서
## 한국 50~60대를 위한 내부 트리거 기반 서비스 설계

**작성일**: 2026-05-16  
**통합 출처**: 리서치 5건 (슈미토 클럽 내부 트리거 분석, 한일 문화 비교, 슈미토 클럽 한국 직도입 문제점, 한국 5060 기능 기획, 소비자-생산자 분리 문제 분석)  
**분석 관점**: 니르 이얄 훅 모델(Hooked)

---

## 설계 북극성

> "오늘도 나는 뭔가 했다 — 그리고 누군가 그것을 알아줬으면 한다."

이 욕구를 해소하는 Bloom 고유의 4가지 설계 원칙:

1. **기존 관계망 재연결** — 새로운 사람이 아닌, 이미 알고 있는 사람과 다시 만나는 설계
2. **체면 보호 기록** — 자랑처럼 보이지 않으면서 존재를 알릴 수 있는 간접 전달 구조
3. **빠른 감정 교환** — "좋아요" 하나로 부족한 한국식 즉각 반응 언어 지원
4. **가족 연결** — 기록이 자녀에게 "나 잘 지내"라는 신호로 자연스럽게 닿는 경로

## Part 1. 벤치마크 — 슈미토 클럽 내부 트리거 분석

### 1-1. 슈미토 클럽이 공략한 내부 트리거 5종

슈미토 클럽(趣味人倶楽部)은 일본 중장년층이 직면하는 심리적 고통을 "취미"라는 긍정적 언어로 포장하여 내부 트리거로 전환한 플랫폼이다. 캐치프레이즈 "趣味でつながる大人のSNS"는 정체성 확인 + 사회적 연결 욕구를 동시에 자극하는 트리거 설계의 결정체다.

| 트리거 | 감정 상태 | 발생 빈도 | 강도 |
|---|---|---|---|
| 사회적 고립감 | "오늘 내가 말을 건 사람이 아무도 없다" | 매일 | ★★★★★ |
| 정체성 공백 | "나는 이제 무엇을 하는 사람인가?" | 주 3~5회 | ★★★★★ |
| 인정 결핍 | "내 노력을 알아봐 주는 사람이 없다" | 매일 | ★★★★½ |
| 무의미함 불안 | "오늘도 아무것도 안 했다" | 매일 오후 2~4시 | ★★★★ |
| 자아실현 열망 | "저 취미를 나도 해보고 싶다" | 주 2~3회 | ★★★★ |

### 1-2. 슈미토 클럽의 훅 사이클

```
[트리거] 고립감 / 정체성 공백 / 인정 결핍
    ↓
[행동] 그룹 피드 탐색 → 댓글 작성 → 취미 기록 게시
    ↓
[가변 보상] 예측 불가능한 댓글·좋아요 수 → 도파민 기반 기대감
    ↓
[투자] 취미 기록 누적 + 그룹 내 관계 형성 → 탈퇴 비용 증가
```

### 1-3. 잘 설계된 부분 vs 개선 기회

**잘 설계된 부분**
- 취미 카테고리 중심 그룹 구조 — 그룹 가입 자체가 "나는 이런 사람이다"라는 정체성 선언
- "어른들의 SNS" 포지셔닝 — 동세대 안전망 확보로 첫 행동 마찰 제거
- 오프라인 이벤트 연결 — 디지털 연결을 현실 관계로 심화하는 투자 메커니즘

**개선 기회**
- 개인화된 트리거 타이밍 알림 미흡
- 정체성 성장 시각화 부족 ("당신은 사진 그룹에서 6개월째 활동 중" 같은 마일스톤 피드백)

## Part 2. 문화 갭 — 슈미토 클럽 직도입의 한계

### 2-1. 핵심 결론

슈미토 클럽 성공의 **60~70%는 일본 특유의 감정 구조**에 기반한다.

| 일본 특수 트리거 | 내용 | 한국 적용 가능성 |
|---|---|---|
| 会社人間 붕괴 | 직장 정체성 상실 후 공허감 | 낮음 (한국은 "아직 현역" 의식) |
| 迷惑 공포 | 타인에게 폐 끼치는 것에 대한 불안 | 낮음 (한국은 적극적 자기표현 선호) |
| おひとりさま 수용 | 혼자 즐기는 문화에 대한 사회적 허용 | 낮음 (한국은 관계 중심) |

이 감정들은 한국 50~60대의 핵심 일상 감정이 아니다. 따라서 UI와 기능 구조를 복사해도 **습관 형성에 필요한 내부 트리거가 작동하지 않아** "가입은 했지만 일상 습관이 되지 못하는" 패턴으로 끝난다.

### 2-2. 한국 vs 일본 문화 차이 7가지

| 항목 | 슈미토 클럽 (일본) | 한국 50~60대 |
|---|---|---|
| 은퇴 태도 | 인생 2막 수용, 소확행 | "아직 현역" 의식, 퇴장 수치심 |
| 연결 방식 | 취미 기반 새로운 인연 | 지연·학연·혈연 우선, 기존 관계망 |
| 감정 표현 | 절제된 조용한 인정 | 즉각적 감탄사 ("어머 너무 예뻐요!!!") |
| 가족 관계 | 개인 활동으로 분리 | 모든 의미 있는 활동이 가족과 연결 |
| 공개 범위 | 커뮤니티 전체 공개 수용 | 아는 사람 중심, 낯선 사람 불안 |
| SNS 목적 | "나는 이런 사람이야" 정체성 선언 | "나는 아직 이런 사람이야" 현역성 입증 |
| 오프라인 전환 | 취미 클럽 정기 모임 의향 높음 | 낯선 사람 경계심으로 전환 의향 낮음 |

### 2-3. 실패했을 요소

| 요소 | 실패 이유 |
|---|---|
| "취미로 연결"이라는 핵심 가치 | 한국에서는 취미가 중심이 아니라 관계가 중심. 취미는 관계를 유지하는 매개일 뿐 |
| 조용한 연결의 문법 | 절제된 UX가 한국의 활기찬 감정 표현 문화와 충돌 |
| 가족 연결 부재 | **가장 치명적 누락.** 기록이 가족에게 닿지 않으면 한국 중장년층에게 기록의 의미는 크게 줄어듦 |

## Part 3. 한국 5060 고유 내부 트리거

### 3-1. 4대 핵심 트리거

**트리거 1 — "아직 살아있다"는 현역성 입증 (★★★★★)**

한국의 50~60대가 가장 강하게 경험하는 감정: "나는 이제 쓸모 있는 사람인가?"  
"오늘 뭐 했어요?"라는 질문은 이 트리거를 정면으로 다룬다. 오늘 내가 무언가를 했다는 기록 자체가 "나는 오늘도 살아서 움직였다"는 존재 증명이다.

> **설계 제언**: 월간·주간 회고 기능. "이번 달 당신은 이런 일들을 했군요"라는 정리가 자동 생성되어, "나는 충실하게 살았다"는 자기 서사를 강화.

**트리거 2 — 가족에게 "걱정 끼치지 않으면서" 존재 알리기 (★★★★★, 한국 고유)**

한국의 50~60대는 자녀에게 잘 지내고 있음을 보여주고 싶지만, "나 오늘 이런 거 했어"라고 카카오톡을 보내는 것은 체면상 부담스럽다. Bloom의 기록이 자녀에게 자연스럽게 전달되는 방식이 이 욕구의 간접적 해소 채널이 된다.

> **설계 제언**: 가족 연결 기능. "부모님이 오늘 텃밭에 다녀오셨어요"라는 부드러운 알림은 자녀에게도 선물.

**트리거 3 — 오래된 관계의 재연결 (★★★★)**

한국 50~60대에게 가장 강력한 감정적 사건 중 하나: 오랜만에 옛 친구나 동창을 만나는 순간. "아, 걔는 지금 뭐하나"라는 호기심과 재연결의 따뜻함.

> **설계 제언**: "새로운 사람 찾기"가 아닌 "이미 아는 사람 다시 만나기" 맥락으로 설계. 카카오 친구 또는 연락처 기반 연결.

**트리거 4 — 감탄사의 문화, 즉각적 감정 교환 (★★★★)**

한국의 50~60대는 빠른 감정적 반응을 원한다. "좋아요" 하나로는 부족하다.

> **설계 제언**: "멋져요", "부러워요", "맛있겠다", "대단해요" 같은 감정 표현 선택지를 풍부하게.

### 3-2. Bloom vs 슈미토 클럽 포지셔닝

| | 슈미토 클럽 | Bloom |
|---|---|---|
| 핵심 트리거 | 会社人間 붕괴, 迷惑 공포 | 현역성 입증, 가족 안도감 선물 |
| 콘텐츠 단위 | 취미 작품 | 오늘의 장면들 |
| 연결 방식 | 새로운 사람 (취미 기반) | 기존 사람 (관계망 기반) |
| 감정 표현 | 조용하고 절제된 인정 | 빠르고 따뜻한 감정 교환 |
| 가족 연결 | 개인 활동으로 분리 | 핵심 동기의 일부 |

슈미토 클럽이 **"취미가 정체성이다"** 라고 말한다면, Bloom은 **"오늘 하루가 정체성이다"** 라고 말해야 한다.

## Part 4. 소비자-생산자 분리 문제 분석

### 4-1. 핵심 문제 진단

생산자(기록하는 사람)는 자기표현 욕구가 충족되지만, **소비자(피드를 보는 사람)는 피드 소비 행동을 유발하는 내부 트리거가 불명확하거나 약하다.**

진짜 원인은 콘텐츠 품질이 아니라 **피드 소비 행동이 소비자 자신의 정체성 서사(Identity Narrative)와 연결되지 않기 때문**이다. 50~60대는 은퇴 전후 "나는 어떻게 살아야 하는가"를 매일 자문한다. 피드가 그 질문에 살아있는 답을 보여줄 때, 소비자는 스스로 생산자가 된다.

### 4-2. 소비자 내부 트리거 5종

| 트리거 | 감정적 공백 | 강도 |
|---|---|---|
| 사회적 비교 불안 | "나만 이렇게 사는 건 아닌가?" | ★★★★★ |
| 정체성 불안 | "은퇴 후 나는 누구인가?" | ★★★★★ |
| 고립감/소외감 | "다들 바쁘게 사는데 나는..." | ★★★★☆ |
| 소속감 결핍 | "나와 비슷한 사람이 있을까?" | ★★★★☆ |
| 영감/자극 욕구 | "저 사람처럼 살아봐야지" | ★★★☆☆ |

### 4-3. 현재 서비스가 트리거를 충족 못하는 이유

- 피드가 "타인의 일기"로 인식 — 나와 무관한 정보
- 나와의 연결고리 부재 — "저 사람 = 나의 미래 가능성"이 보이지 않음
- 소비 행동에 능동성 없음 — 좋아요 하나뿐

### 4-4. Hook Model 4단계 매핑

**트리거**

| 외부 트리거 | 내부 트리거 연결 | 알림 문구 예시 |
|---|---|---|
| 오전 8~9시 알림 | "오늘도 활동적인 나" 정체성 | "이웃 김정숙님이 오늘 아침 산책을 기록했어요. 오늘 하루도 활기차게 시작하실 건가요?" |
| 오후 3~4시 알림 | "나만 아무것도 안 하는" 공허감 | "오늘 오후에만 벌써 23명이 활동을 기록했어요. 한 줄 남겨볼까요?" |
| 팔로워 체크인 알림 | 연결감 확인 | "이웃 박순자님이 오늘도 텃밭에서 땀 흘렸대요. 응원해드릴까요?" |

**행동** — 단계 수 최소화

| 경로 | 현재 | 목표 |
|---|---|---|
| 일반 체크인 | 4단계 | 4단계 유지 |
| 간편 체크인 | 2단계 | 2단계 유지 |
| "나도 했어요" (신규) | 없음 | **1단계** |

**가변 보상** — 50~60대에게 효과적인 보상 유형

| 유형 | 내용 | 가변성 원천 |
|---|---|---|
| 사회적 보상 | "나도 해봐야지 7명" 반응 확인 | 누가 어떤 반응을 남겼는지 예측 불가 |
| 자기 보상 | "이번 주 평소보다 2배 활동!" 비교 피드백 | 자신의 활동 패턴을 완전히 알지 못함 |
| 탐색 보상 | 피드에서 예상치 못한 기록 발견 | 매일 다른 사람들의 완전히 다른 이야기 |

**투자**

| 유형 | 내용 | 전환 비용 효과 |
|---|---|---|
| 데이터 | 캘린더 히트맵 1년치 기록 | "이것을 버리고 다른 앱으로 갈 수 없다" |
| 관계 | 이웃의 일상 컨텍스트 공유 누적 | 암묵적 관계 형성 |
| 콘텐츠 | 카테고리별 사진 갤러리 | 1년치 사진이 쌓이면 이탈 불가 |

### 4-5. 소비자→생산자 전환 티핑 포인트

전환은 다음 3조건이 동시에 충족될 때 발생한다:

1. **사회적 압력** — 팔로우한 사람 대부분이 이미 기록 중
2. **마찰 제로** — "나도 했어요" 원탭으로 글 안 써도 됨
3. **안전한 첫 기록** — 빈 텍스트 박스가 아닌, 카테고리 자동 선택 상태

첫 등록이 쉽고 긍정적이면 두 번째 등록은 상세 모드로 자연스럽게 이어진다. 이것이 훅 모델의 **나선형 심화(Spiral Deepening)** 구조다.

## Part 5. Bloom 기능 설계 — 트리거 해소 방안

### 5-1. 기능 1. 감정 반응 표현판 (리액션 5종)

**해소 트리거**: 사회적 고립감 (★★★★★) + 인정 결핍

**핵심**: "좋아요" 하나로는 부족한 한국 중장년의 감탄사 문화를 반영한 5종 감정 반응.

| 리액션 | 텍스트 | 어울리는 상황 |
|---|---|---|
| 기본 하트 | 좋아요 | 범용 |
| 음식 그릇 | 맛있겠다 | 요리, 외식 |
| 박수 | 대단해요 | 운동, 성취 |
| 반짝이 | 부러워요 | 나들이, 여행 |
| 따뜻한 손 | 잘했다 | 범용 응원 |

> 이모지 없이 **한글 텍스트 버튼**으로 구성. 피드 카드에서 하트 바로 클릭 → 기존 좋아요 유지, "▾" 탭 → 리액션 팝오버 등장.

**구현**: `likes` 테이블에 `reaction_type` 컬럼 추가 (ENUM: `LIKE`, `DELICIOUS`, `GREAT`, `ENVIOUS`, `WELL_DONE`). 기존 `useLikeToggle` 패턴 확장. 예상 3~4일.

---

### 5-2. 기능 2. 나와 같은 N명 배너 → 탭 가능하게

**해소 트리거**: 소속 욕구 + 연결 기대

**현재 문제**: "나와 같은 활동을 한 N명이 있어요!" 배너를 탭해도 아무 반응 없는 **막다른 길**.

**개선**: 배너 탭 → 바텀시트로 해당 카테고리 오늘 활동자 목록 + 팔로우 버튼 표시.

**구현**: 카테고리 기반 오늘의 활동자 목록 API 신설. 기존 팔로우 기능 재사용. 예상 2~3일.

---

### 5-3. 기능 3. "나도 했어요" 원탭 버튼

**해소 트리거**: 동질감 충동 + 마찰 제거

**핵심**: 소비자→생산자 전환의 가장 짧은 경로. 피드 카드 하단에 버튼 하나 추가 → 해당 카드와 같은 카테고리로 즉시 체크인 등록 (내용 입력 없음).

**구현**: 기존 `useCreateCheckin` 훅 + `AUTO_TITLES` 상수 재활용. 백엔드 변경 없음. 예상 1일.

---

### 5-4. 기능 4. 오늘의 참여 온도

**해소 트리거**: FOMO + 무료함

피드 헤더 아래 한 줄: "오늘 오전에만 벌써 23명이 활동을 기록했어요."

**구현**: 피드 응답에 오늘의 총 체크인 수 추가. 예상 0.5일.

---

### 5-5. 기능 5. 월간 리포트 (이달의 나)

**해소 트리거**: 역할 상실감 (★★★★★) + 현역성 증명 욕구 (★★★★)

**핵심**: 매월 1일, "지난달 당신이 이런 일들을 하셨네요"라는 개인화 활동 요약으로 "나는 충실하게 살았다"는 자기 서사를 강화.

**화면 구성**:
- 헤드라인 카드: "[4월의 김철수님] 총 16일 기록 · 활동 19회"
- 캘린더 히트맵: 기록한 날 primary 컬러, 기록 없는 날 강조 없음 (부정 프레이밍 금지)
- 카테고리 도넛 차트
- 받은 공감 요약
- 이달의 하이라이트 체크인 3개

**구현**: `GET /api/users/me/monthly-report?year={year}&month={month}`. 기존 `useMyCalendar`, `useMyCategoryStats` 훅 재활용. 예상 3~4일.

---

### 5-6. 기능 6. 가족 연결 (패밀리 링크)

**해소 트리거**: 가족 연결 욕구 (★★★★★, 한국 고유)

**핵심**: 자녀가 부모의 Bloom 활동을 간접적으로 받아볼 수 있는 선택적 가족 연결. 부모는 "기록"하고, 자녀는 "안부"를 받는다.

**프라이버시 원칙**:
- 가족 연결은 양방향 동의 필수
- 언제든 연결 해제 가능, 해제 시 자녀 알림 없음
- 부모가 원하는 체크인만 "가족 공개" 설정 가능

**구현**: 신규 `family` 도메인 패키지 신설. 예상 7~10일.

---

### 5-7. 기능 7. 오늘의 한 마디 (간편 체크인)

**해소 트리거**: 역할 상실감 + 무의미함 불안

**핵심**: 사진도 없고, 길게 쓸 말도 없을 때 단 한 줄만으로 오늘을 기록. 기록의 최소 가능 단위를 낮춰 진입 장벽 제거.

**흐름**: 카테고리 탭 1번 → 자동 제목 생성 → 한 줄 설명(선택) → 등록

**구현**: 백엔드 변경 없음. 프론트 `FeedPage` 인라인 체크인 폼 리팩토링. 예상 1~2일.

---

### 5-8. 기능 8. 칭찬 카드 (응원 메시지)

**해소 트리거**: 역할 상실감 + 체면 손상 불안

**핵심**: 댓글보다 부담 적고, 좋아요보다 온기 있는 중간 단계의 감정 표현. 미리 만들어진 따뜻한 문장으로 서로 응원.

카테고리별 자동 조정: 요리 → "맛있어 보여요!", 운동 → "대단해요!", 독서 → "어떤 책인지 궁금해요"

**구현**: `comments` 테이블에 `comment_type` 컬럼 추가. 기존 댓글 API 확장. 예상 2~3일.

---

### 5-9. 기능 9. 옛 인연 다시 만나기

**해소 트리거**: 사회적 고립감 + 기존 관계망 욕구

**핵심**: 새로운 사람이 아닌, 이미 알고 있는 사람(동창, 옛 동료, 이웃)을 Bloom에서 다시 만날 수 있는 관계망 재연결.

**연결 방법**: 카카오 친구 API, Android Chrome Contacts Picker API, 닉네임 직접 검색 (fallback)

**구현**: 신규 `follow` 도메인 패키지. 카카오 친구 API 연동. 예상 10~14일.

---

## Part 6. 기능 우선순위 종합

### 구현 우선순위 매트릭스

| 우선순위 | 기능 | 해소 트리거 | 난이도 | 단계 |
|---|---|---|---|---|
| P0 | "나도 했어요" 버튼 | 동질감, 마찰 제거 | 낮음 (1일) | MVP+1 |
| P0 | 감정 반응 5종 | 사회적 고립감, 인정 결핍 | 낮음 (3~4일) | MVP+1 |
| P0 | 오늘의 한 마디 (간편 체크인) | 역할 상실감, 무의미함 | 낮음 (1~2일) | MVP+1 |
| P1 | "나와 같은 N명" 배너 탭 | 소속 욕구, 연결 기대 | 중간 (2~3일) | MVP+1 |
| P1 | 오늘의 참여 온도 | FOMO, 무료함 | 낮음 (0.5일) | MVP+1 |
| P1 | 월간 리포트 | 역할 상실감, 현역성 증명 | 중간 (3~4일) | MVP+1 |
| P1 | 가족 연결 | 가족 연결 욕구 (한국 고유) | 높음 (7~10일) | MVP+1 |
| P2 | 칭찬 카드 | 역할 상실감, 체면 손상 불안 | 낮음 (2~3일) | MVP+2 |
| P2 | 주간 활동 리포트 카드 | 자기 효능감, 가변 보상 | 중간 | MVP+2 |
| P2 | 카테고리별 사진 갤러리 | 콘텐츠 투자 자산화 | 중~높음 | MVP+2 |
| P3 | 옛 인연 다시 만나기 | 사회적 고립감 | 높음 (10~14일) | MVP+2 |

### 개발 단계별 로드맵

**MVP+1 (권장 순서)**
1. 오늘의 한 마디 — 백엔드 없음. 예상 1~2일.
2. "나도 했어요" 버튼 — 백엔드 없음. 예상 1일.
3. 감정 반응 5종 — like 도메인 확장. 예상 3~4일.
4. 오늘의 참여 온도 + "나와 같은 N명" 배너 탭. 예상 3일.
5. 월간 리포트 — 집계 API 신설. 예상 3~4일.
6. 가족 연결 — 신규 도메인. 예상 7~10일.

**MVP+2**
7. 칭찬 카드 — 댓글 도메인 확장. 예상 2~3일.
8. 주간 활동 리포트 카드.
9. 카테고리별 사진 갤러리.
10. 옛 인연 다시 만나기 — follow 도메인 + 카카오 연동. 예상 10~14일.

## Part 7. 공통 설계 원칙

### 50~60대 UX 원칙

| 원칙 | 설계 결정 |
|---|---|
| 텍스트 최소 18px+ | 기존 디자인 시스템 기준 (text-base 이상) |
| 버튼 터치 타겟 48px+ | 리액션 버튼, 칭찬 카드 모두 h-12 이상 |
| 한 화면에 한 가지 액션 | 간편 체크인: 카테고리 → 텍스트 → 등록 단계별 진행 |
| 실수 허용 설계 | 가족 연결 해제: "정말 해제하시겠어요?" 확인 단계 필수 |
| 친숙한 언어 | "팔로우" 대신 "관심 있어요", "링크" 대신 "연결하기" |
| 빈 화면 설계 | 리포트 첫 달: "아직 기록이 없어요. 오늘 첫 기록을 남겨보세요" |

### 체면 보호 설계

- **팔로우 목록 비공개**: "저 사람이 날 안 팔로우하네"라는 비교 상황 방지
- **칭찬 카드 선택지 제공**: "어떻게 써야 하나" 고민 없이 따뜻한 말 전달
- **간편 체크인의 소박함 허용**: 사진 없이 "산책" 한 단어도 기록으로 인정
- **월간 리포트의 긍정 프레이밍**: 기록하지 않은 날 강조 없음
- **가족 연결의 간접성**: 부모가 직접 말하지 않아도 기록이 대신 전달

### 잠재적 기술 리스크

| 리스크 | 영향 | 대응 방안 |
|---|---|---|
| iOS Safari Contacts Picker API 미지원 | 중 | iOS는 카카오 친구 API로 대응 |
| 가족 연결 — 비회원 자녀 조회 링크 | 중 | 초기에는 자녀도 Bloom 가입 필요 |
| 리액션 팝오버 존재 인식 부족 | 낮음 | 상세 화면에서 5개 버튼 항상 노출 |
| 월간 리포트 집계 쿼리 성능 | 낮음 | Redis 캐시 또는 스케줄 배치 고려 |
