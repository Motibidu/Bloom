# Bloom 신규 기능 기획서
## 한국 50~60대 내부 트리거 해소를 위한 차별화 기능 설계

**작성일**: 2026-05-11  
**기준 컨텍스트**: 리서치 3건 (슈미토 클럽 분석, 한일 문화 비교, 한국 5060 트리거 분석)  
**현재 구현 기능**: 체크인, 피드, 좋아요, 댓글, 사진 업로드(최대 3장), 카테고리 필터, 마이 활동 히스토리

---

## 설계 원칙 요약

리서치 3건의 공통 결론은 다음 한 문장으로 압축된다.

> "오늘도 나는 뭔가 했다 — 그리고 누군가 그것을 알아줬으면 한다."

이 욕구를 해소하는 Bloom 고유의 4가지 설계 원칙:

1. **기존 관계망 재연결** — 새로운 사람이 아닌, 이미 알고 있는 사람과 다시 만나는 설계
2. **체면 보호 기록** — 자랑처럼 보이지 않으면서 존재를 알릴 수 있는 간접 전달 구조
3. **빠른 감정 교환** — "좋아요" 하나로 부족한 한국식 즉각 반응 언어 지원
4. **가족 연결** — 기록이 자녀에게 "나 잘 지내"라는 신호로 자연스럽게 닿는 경로

## 기능 1. 감정 반응 표현판 (공감 리액션)

**해결하는 트리거**: 사회적 고립감 (★★★★★) + 인정 결핍

**핵심 아이디어**: "좋아요" 하나로는 부족한 한국 중장년의 감탄사 문화를 반영하여, 상황에 맞는 5종 감정 반응을 제공한다.

### 사용자 시나리오

**페르소나**: 박영숙 (58세, 서울 마포구 거주, 전업주부)  
텃밭에서 처음으로 상추를 수확했다. 사진을 Bloom에 올렸고, 20분 뒤 알림이 왔다. "맛있겠다 3명", "대단해요 2명". 단순한 숫자가 아니라 자신의 작은 성취가 구체적으로 인정받은 느낌이다. "내 친구 이순희씨가 '잘했다'고 눌렀네" — 실명 반응을 확인하는 순간 온기가 전해진다.

### 화면 설명

**피드 카드 / 상세 화면 하단 반응 영역**

현재 좋아요 버튼 위치를 확장하여 5종 리액션 선택 영역으로 교체한다.

| 리액션 | 텍스트 | 어울리는 상황 |
|---|---|---|
| 기본 하트 | 좋아요 | 범용 |
| 음식 그릇 | 맛있겠다 | 요리, 외식 카테고리 |
| 박수 | 대단해요 | 운동, 성취 |
| 반짝이 | 부러워요 | 여행, 나들이 |
| 따뜻한 손 | 잘했다 | 범용 응원 |

**UX 흐름**:
- 피드 카드에서 하트 버튼 옆 **"반응 더보기" 버튼(▾)을 클릭하면** 리액션 선택 팝오버 등장
- **하트 버튼을 바로 클릭하면** 기존처럼 "좋아요" 즉시 반응 (50~60대 단순 클릭 패턴 유지)
- 상세 화면에서는 5개 버튼이 항상 노출

**반응 집계 표시**:
- 피드 카드: 가장 많이 눌린 리액션 1종 + 총 합계 숫자 (예: "대단해요 외 7")
- 상세 화면: 리액션별 숫자 + "홍길동, 이순희 외 2명" 형태로 실명 노출

### 핵심 인터랙션

- "반응 더보기" 버튼 클릭 → 리액션 선택 팝오버 (ShadcnUI Popover 활용)
- 낙관적 업데이트 유지 (기존 `useLikeToggle` 패턴 확장)
- 리액션 변경 가능: 한 번 누른 리액션을 다른 것으로 교체 (본인 기준 1개만 유지)

### 한국 문화 연결 포인트

"어머 너무 예뻐요!!!" — 한국 중장년의 감탄사 문화. 일본의 조용한 존재감이 아닌, 즉각적이고 따뜻한 감정 교환. "잘했다"는 표현은 동년배 간의 격려 언어로, 단순 숫자보다 훨씬 강한 인정 신호다.

### 구현 우선순위: 높음 (MVP+1)

기존 좋아요 인프라(like 도메인, `useLikeToggle`, 낙관적 업데이트) 위에 확장하는 구조라 공수가 적다.

**구현 범위**:
- DB: `likes` 테이블에 `reaction_type` 컬럼 추가
  - ENUM: `LIKE`, `DELICIOUS`, `GREAT`, `ENVIOUS`, `WELL_DONE`
- API: `POST /api/checkins/{id}/like` 요청 body에 `reactionType` 추가
- 기존 `like` 도메인 확장, 별도 도메인 불필요
- 프론트: `src/components/ui/domain/checkin/reaction-picker.tsx` 신규 컴포넌트

## 기능 2. 나의 활동 월간 리포트 (이달의 나)

**해결하는 트리거**: 역할 상실감 (★★★★★) + 현역성 증명 욕구 (★★★★)

**핵심 아이디어**: 매월 1일, "지난달 당신이 이런 일들을 하셨네요"라는 개인화된 활동 요약을 보여줘 "나는 충실하게 살았다"는 자기 서사를 강화한다.

### 사용자 시나리오

**페르소나**: 김철수 (62세, 부산 해운대구, 은퇴 2년차 전직 은행원)  
매월 1일 아침, Bloom에서 알림이 온다. "4월 한 달 동안 어떻게 지내셨는지 확인해 보세요." 앱을 열면 — "4월의 김철수님: 산책 8번, 독서 5번, 요리 3번. 총 16일 기록하셨어요." 수치가 아니라 이야기처럼 보인다. 캘린더 히트맵에서 빼곡하게 채워진 날들을 보며 "나 이달에 정말 잘 살았다"는 감각이 온다.

### 화면 설명

**SCR-R01 월간 리포트 화면** (진입: 마이 활동 페이지 → "이달의 기록 보기" 또는 월초 알림 클릭)

**섹션 1 — 헤드라인 카드**
```
[4월의 김철수님]
총 16일 기록 · 활동 19회
"4월엔 주로 걷기와 독서를 하셨네요"
```
배경: 해당 월에 가장 많이 기록한 카테고리의 테마 색상

**섹션 2 — 캘린더 히트맵**
- 월별 달력, 기록한 날은 primary 컬러로 채워짐
- 기록이 없는 날은 회색 (강조 없음 — "못한 날" 부각 금지)

**섹션 3 — 카테고리 도넛 차트**
- 이번 달 활동 카테고리 비율
- 가장 많이 한 활동 1위를 텍스트로 강조

**섹션 4 — 받은 공감 요약**
- "이번 달 받은 반응: 대단해요 12번, 좋아요 9번, 맛있겠다 6번"
- 가장 많이 받은 반응 하나를 크게 표시

**섹션 5 — 이달의 하이라이트 (3장)**
- 좋아요/리액션을 가장 많이 받은 체크인 카드 3개
- 레이블: "많은 분들이 좋아하셨어요"

**하단 CTA**
- "이번 달도 오늘부터 시작해요" → 피드 작성 화면으로 이동

### 한국 문화 연결 포인트

**빨리빨리 문화의 역설**: 아무것도 안 하는 것에 극도의 불편함을 느끼는 한국 5060에게, "나는 이달에 이만큼 했다"는 증거가 강력한 현역성 입증이 된다. "활동량의 축적"이 아닌 "살아낸 하루들의 이야기"로 프레이밍.

### 구현 우선순위: 높음 (MVP+1)

기존 `useMyCalendar`, `useMyCategoryStats` 훅 재활용. 집계 API 1~2개 추가로 구현 가능.

**구현 범위**:
- API: `GET /api/users/me/monthly-report?year={year}&month={month}`
  - 응답: 기록일수, 총 활동수, 카테고리 분포, 받은 리액션 집계, 인기 체크인 3개
- 프론트: `/me/report?month=2026-04` 라우트
- 기존 `CheckinRepository`에 집계 쿼리 추가

## 기능 3. 가족 연결 — 조용한 안부 전달 (패밀리 링크)

**해결하는 트리거**: 가족 연결 욕구 (★★★★★, 한국 고유)

**핵심 아이디어**: 자녀가 부모의 Bloom 활동을 간접적으로 받아볼 수 있는 선택적 가족 연결 기능. 부모는 "기록"하고, 자녀는 "안부"를 받는다. 직접 전화하지 않아도 되는 간접 연결 구조.

### 사용자 시나리오

**페르소나**: 이정숙 (59세, 경기 고양시) + 자녀 이민준 (32세, 서울 직장인)

이정숙 씨는 오늘 아침 한강 산책을 기록했다. 별다른 행동 없이 평소대로 Bloom에 올렸을 뿐이다. 그날 저녁, 이민준 씨의 이메일(또는 카카오톡 공유 링크)로 알림이 왔다: "어머니가 오늘 한강 산책을 다녀오셨어요. Bloom에서 확인하세요." 이민준은 링크를 눌러 어머니의 기록을 본다. "다행이다, 잘 지내시네."

### 화면 설명

**SCR-F01 가족 연결 설정 화면** (프로필 페이지 → "가족과 연결하기")

연결 전:
```
[연결된 가족 없음]
"가족이 내 활동을 조용히 볼 수 있도록 연결해 보세요"
[가족 초대하기] 버튼
```

연결 후:
```
[이민준 (아들)]  연결됨 · 2026.04.15부터
알림 설정: 매일 저녁 요약 / 실시간 / 끄기
[연결 해제]
```

**SCR-F02 가족 초대 화면**
```
"이 링크를 자녀에게 보내세요"
[링크 복사하기] [카카오톡 공유하기]
링크 유효기간: 24시간
```
> "카카오톡 공유하기"는 카카오 JavaScript SDK(`Kakao.Share.sendDefault`)를 사용. 앱 설치 없이 웹에서 동작하며, 클릭 시 카카오톡 앱으로 공유 시트 열림.

**자녀 수락 화면 (자녀 측)**:  
초대 링크 클릭 → Bloom 웹사이트로 이동 → "이정숙님이 가족으로 연결 요청을 보내셨어요. 수락하면 어머님의 활동 기록을 조용히 볼 수 있습니다."  
[수락하기] [거절하기]  
> 자녀가 비회원인 경우 간편 가입(이메일) 후 수락. 자녀 계정 없이도 읽기 전용 링크 접근은 2단계에서 검토.

**알림 수신 설정 (자녀 측)**:
- 실시간 이메일 알림: 부모가 체크인 할 때마다
- 매일 저녁 요약 이메일: 하루 활동 1회 요약
- 주간 요약 이메일: 이번 주 활동 모아보기
- 알림 끄기: Bloom에 직접 방문하여 확인
> 웹 푸시(Web Push API)는 2단계에서 검토. 초기에는 이메일 알림으로 구현.

### 핵심 인터랙션

**부모 측 경험**: 기존 기록 행동과 완전히 동일 — 아무것도 추가로 하지 않아도 된다.

**자녀 측 경험**: 카카오톡 알림 링크 → 부모의 Bloom 프로필(읽기 전용) 접근 가능.

**프라이버시 원칙**:
- 가족 연결은 양방향 동의 필수
- 부모가 원하는 체크인만 "가족 공개" 설정 가능 (기본값: 전체 공개)
- 언제든 연결 해제 가능, 해제 시 자녀 알림 없음

### 한국 문화 연결 포인트

**체면 + 가족 중심주의의 결합**: "나 이렇게 잘 살고 있어, 걱정 마"를 카카오톡으로 직접 보내는 것은 체면상 부담스럽다. 그러나 Bloom에 평소처럼 기록해두면, 그 기록이 간접적으로 전달된다. 정(情)의 디지털화 — 공들여 찾아가는 것이 아니라, 일상이 자연스럽게 흐르는 구조.

### 구현 우선순위: 높음 (MVP+1 최우선)

한국 50~60대 고유의 차별화 트리거를 해소하는 기능. 슈미토 클럽이 전혀 갖추지 못한 Bloom만의 강점.

**구현 범위**:

신규 도메인 `family` 패키지 신설:

```
com.starterkit.domain.family/
├── entity/FamilyLink.java
│   fields: id, requesterId, receiverId, status(PENDING/ACTIVE/BLOCKED),
│           notificationFrequency, createdAt
├── dto/request/FamilyLinkRequest.java
├── dto/response/FamilyLinkResponse.java
├── repository/FamilyLinkRepository.java
├── service/FamilyLinkService.java
└── controller/FamilyLinkController.java
```

| Method | Path | 설명 | 인증 |
|---|---|---|---|
| POST | /api/family/invite | 초대 링크 토큰 생성 | 필요 |
| POST | /api/family/accept | 토큰으로 연결 수락 | 필요 |
| GET | /api/family/links | 내 연결된 가족 목록 | 필요 |
| DELETE | /api/family/links/{id} | 연결 해제 | 필요 |
| PATCH | /api/family/links/{id}/notification | 알림 빈도 설정 | 필요 |
| GET | /api/users/{id}/public-checkins | 가족 공개 체크인 조회 | 선택적 |

## 기능 4. 옛 인연 다시 만나기 (동창/이웃 찾기)

**해결하는 트리거**: 사회적 고립감 (★★★★★) + 현역성 증명 욕구 (★★★★)

**핵심 아이디어**: 슈미토 클럽처럼 새로운 사람을 찾는 것이 아니라, 이미 알고 있는 사람(동창, 옛 동료, 이웃)을 Bloom에서 다시 만날 수 있는 "관계망 재연결" 기능.

### 사용자 시나리오

**페르소나**: 최순자 (56세, 대전 유성구, 동네 반모임 임원)  
Bloom 회원가입 후 "혹시 아는 분 있으면 찾아보세요" 안내가 나온다. 카카오 친구 찾기를 누르니 "카카오 친구 중 Bloom을 쓰고 계신 분을 찾아드릴게요" 안내가 나온다. 카카오 동의 후 "연락처에 있는 3명이 Bloom을 쓰고 있어요"라는 결과가 나온다. 그 중에 10년 전 같은 아파트에 살던 박미영 씨가 있다. "어머, 얘도 여기 있네." 팔로우 버튼을 누르고 박미영 씨의 피드를 보니 요즘 수채화를 배우고 있다.

### 화면 설명

**SCR-N01 사람 찾기 화면** (하단 탭 또는 피드 상단 "아는 분 찾기" 배너)

**섹션 1 — 아는 분 찾기**
```
[카카오 친구에서 찾기]                     ← iOS/Android 웹 모두 동작
"카카오 친구 중 Bloom을 쓰시는 분을 찾아드려요"
[카카오로 찾기] 버튼

────────────────────────  (Android Chrome 한정 추가 노출)
[핸드폰 연락처에서 찾기]
"연락처는 찾기에만 사용하며 저장하지 않아요"
```

**섹션 3 — 팔로우 관리**  
내가 팔로우한 사람들의 활동을 별도 탭 "내 사람들 피드"로 분리

### 핵심 인터랙션

**팔로우 시스템**:
- 일방 팔로우 (상대 승인 불필요) — 심리적 진입 장벽 최소화
- 팔로우하면 해당 사람의 체크인이 피드 상단에 우선 노출
- 팔로우 목록은 비공개 (체면 보호)

**안부 인사하기 버튼**:
- 첫 연결 시 "반갑습니다!" 템플릿 제공
- 50자 이내 커스텀 입력도 가능
- 상대에게 알림: "최순자님이 안부를 전했어요"

### 한국 문화 연결 포인트

**정(情)과 지연·학연**: 한국 5060의 사회적 연결은 취미 기반이 아니라 이미 쌓인 관계(지연, 학연, 직장 인연)에서 온다. "취미가 같은 낯선 사람"보다 "10년 만에 다시 만나는 같은 동네 친구"가 훨씬 강한 감정적 반응을 일으킨다.

### 구현 우선순위: 중간 (MVP+2)

팔로우 도메인 신설, 카카오 친구 API 연동 등 공수가 크다.

**구현 범위**:

신규 도메인 `follow` 패키지 신설:

```
com.starterkit.domain.follow/
├── entity/Follow.java
│   fields: id, followerId, followingId, createdAt
├── repository/FollowRepository.java
├── service/FollowService.java
└── controller/FollowController.java
```

| Method | Path | 설명 | 인증 |
|---|---|---|---|
| POST | /api/follows/{userId} | 팔로우 | 필요 |
| DELETE | /api/follows/{userId} | 언팔로우 | 필요 |
| GET | /api/feeds/following | 팔로우 중인 사람들 피드 | 필요 |
| POST | /api/users/find-by-contacts | 연락처 해시 배열로 회원 조회 | 필요 |
| GET | /api/users/search?q={query} | 닉네임/이름 직접 검색 | 필요 |

**연락처 연동 환경별 구현 전략**:

| 환경 | 방법 | 지원 여부 |
|---|---|---|
| iOS Safari / Android 웹 | 카카오 친구 API (카카오 OAuth 동의) | ✅ 전 환경 공통 |
| Android Chrome 웹 | Contacts Picker API (네이티브 연락처) | ✅ 추가 지원 |
| React Native 앱 (향후) | JS Bridge → `react-native-contacts` | ✅ iOS/Android 모두 |
| 모든 환경 공통 | 닉네임/이름 직접 검색 | ✅ fallback |

- 카카오 친구 API: Kakao JavaScript SDK 사용, 비즈니스 앱 심사 필요
- 연락처 해시: 클라이언트에서 전화번호를 SHA-256 해시로 변환 후 전송 (원본 저장 금지)
- 환경 감지: `window.ReactNativeWebView` 존재 여부로 앱/웹 분기

## 기능 5. 작은 칭찬 카드 (응원 메시지)

**해결하는 트리거**: 역할 상실감 (★★★★★) + 체면 손상 불안 (★★★★)

**핵심 아이디어**: 댓글보다 부담이 적고, 좋아요보다 온기가 있는 중간 단계의 감정 표현. 미리 만들어진 따뜻한 문장으로 서로 응원한다.

### 사용자 시나리오

**페르소나**: 강병호 (61세, 광주 남구, 은퇴 전직 교사)  
황명숙 씨가 처음으로 자전거를 탔다는 기록을 올렸다. 댓글을 쓰고 싶은데 뭐라고 써야 할지 막막하다. 체크인 카드 하단에 "칭찬 카드 보내기" 버튼이 있다. 눌러보니 "멋져요, 오늘도 파이팅!", "부러워요, 저도 해보고 싶어요" 등의 카드가 나온다. 한 번 탭하니 황명숙 씨에게 알림이 간다.

### 화면 설명

**체크인 상세 화면 내 칭찬 카드 영역**

```
[칭찬 카드 보내기]
────────────────────────────────
┌─────────────────┐  ┌─────────────────┐
│ 멋져요,         │  │ 부러워요,       │
│ 오늘도 파이팅!  │  │ 저도 해보고     │
│                 │  │ 싶어요          │
└─────────────────┘  └─────────────────┘
┌─────────────────┐  ┌─────────────────┐
│ 응원할게요!     │  │ 대단하세요!     │
└─────────────────┘  └─────────────────┘
            [직접 쓰기 →] (50자 이내)
```

카드 탭 → 즉시 전송 확인 애니메이션 → "전달되었어요" 토스트

**카테고리별 카드 자동 조정**:
- 요리: "맛있어 보여요!", "레시피 알려주세요"
- 운동: "대단해요, 저도 힘낼게요!"
- 독서: "어떤 책인지 궁금해요"

### 한국 문화 연결 포인트

**댓글 장벽 해소**: 한국 중장년층이 SNS 참여를 망설이는 가장 큰 이유 중 하나가 "댓글을 어떻게 써야 하나"는 막막함이다. 칭찬 카드는 이 장벽을 제거하면서도, 숫자 카운트에 그치지 않는 온기를 전달한다. 快(빠른) + 情(따뜻한) 감정 교환.

### 구현 우선순위: 중간 (MVP+2)

기능 1(리액션) 구현 후 자연스러운 확장.

**구현 범위**:
- DB: `comments` 테이블에 `comment_type` 컬럼 추가
  - ENUM: `TEXT`, `PRAISE_CARD`
  - `praise_card_template_id` 컬럼 추가
- API: 기존 `POST /api/comments` 확장 — `commentType: 'PRAISE_CARD'`, `praiseCardId: 3`
- 카드 템플릿: 카테고리별 정적 목록 (코드 상수로 관리, DB 불필요)

## 기능 6. 오늘의 한 마디 (간편 체크인)

**해결하는 트리거**: 역할 상실감 (★★★★★) + 무의미함 불안

**핵심 아이디어**: 사진도 없고, 길게 쓸 말도 없을 때, 단 한 줄만으로 오늘을 기록할 수 있는 초간편 체크인 모드. 기록의 최소 가능 단위를 낮춰 진입 장벽을 제거한다.

### 사용자 시나리오

**페르소나**: 윤복희 (64세, 인천 연수구, 주부, 디지털 기기 어려움)  
Bloom을 알게 됐는데, 사진도 찍어야 하고 글도 써야 한다고 생각하니 엄두가 안 난다. 피드 상단에 "오늘의 한 마디" 영역이 있다. "산책"을 탭하면 "오늘 산책을 하셨군요. 한 줄 덧붙이시겠어요?" 입력창이 나온다. "아침에 공원 한 바퀴."를 입력하고 등록 버튼을 누른다. 완성.

### 화면 설명

**피드 페이지 최상단 — 오늘의 한 마디 영역**

**기본 모드 (간편 모드)**:
```
┌─────────────────────────────────────────────┐
│  오늘 뭐 하셨어요?                           │
│                                              │
│  [산책] [요리] [독서] [텃밭]                 │
│  [운동] [모임] [기타]                        │
│                                              │
│  카테고리를 탭하면 바로 기록할 수 있어요     │
└─────────────────────────────────────────────┘
```

**카테고리 탭 후**:
```
┌─────────────────────────────────────────────┐
│  [산책] 산책을 하셨군요!                     │
│                                              │
│  오늘 산책이 어땠나요? (선택 사항)           │
│  ┌─────────────────────────────────────┐    │
│  │ 예: 아침에 공원 한 바퀴 돌았어요    │    │
│  └─────────────────────────────────────┘    │
│                                              │
│  [+ 사진 추가] (선택)                        │
│                                              │
│  [기록하기] 버튼 (크게, 항상 활성화)         │
└─────────────────────────────────────────────┘
```

"더 자세히 기록하고 싶으신가요?" → 기존 전체 체크인 폼으로 전환 링크

### 핵심 인터랙션

- 카테고리 탭 1번 → 즉시 제목 자동 생성 ("산책") → 한 줄 설명만 입력하면 완료
- 텍스트 입력 없어도 등록 가능 (카테고리만으로 완성)
- 소박한 일상도 당당하게 기록할 수 있다는 문화적 허용을 설계 안에 내재

### 한국 문화 연결 포인트

**빨리빨리 + 체면**: 한국 5060에게 기록의 의미는 "오늘 내가 이걸 했다"는 사실의 확인이다. 아침 산책 한 바퀴, 저녁 드라마 한 편도 기록이 된다. "사진이 없으면 올리면 안 되나?"라는 체면 불안을 없애는 설계.

### 구현 우선순위: 높음 (MVP+1, 공수 가장 적음)

백엔드 변경 없음. 프론트 UX 개선만으로 구현 가능.

**구현 범위**:
- 백엔드 변경 없음
- 프론트: `FeedPage`의 인라인 체크인 폼을 간편 모드/상세 모드 방식으로 리팩토링
- `category-icon-grid.tsx` 재활용, 카테고리 탭 시 자동 제목 생성 로직 추가

## 공통 UX 원칙 — 50~60대 기준

| 원칙 | 설계 결정 |
|---|---|
| 텍스트 최소 16px+ | 기존 디자인 시스템 기준 유지 |
| 버튼 터치 타겟 48px+ | 리액션 버튼, 칭찬 카드 모두 h-12 이상 |
| 한 화면에 한 가지 액션 | 간편 체크인: 카테고리 → 텍스트 → 등록 단계별 진행 |
| 실수 허용 설계 | 가족 연결 해제: "정말 해제하시겠어요?" 확인 단계 필수 |
| 친숙한 언어 | "팔로우" 대신 "관심 있어요", "링크" 대신 "연결하기" |
| 빈 화면 설계 | 리포트 첫 달: "아직 기록이 없어요. 오늘 첫 기록을 남겨보세요" |

## 체면 보호 설계 (특별 강조)

한국 5060의 체면 문화를 고려한 구체적 설계 결정:

- **팔로우 목록 비공개**: "저 사람이 날 안 팔로우하네"라는 비교 상황 방지
- **칭찬 카드 선택지 제공**: "어떻게 써야 하나" 고민 없이 따뜻한 말 전달 가능
- **간편 체크인의 소박함 허용**: 사진 없이 "산책" 한 단어도 기록으로 인정
- **월간 리포트의 긍정 프레이밍**: 기록하지 않은 날 강조 없음, "이만큼 하셨네요"로만 표현
- **가족 연결의 간접성**: 부모가 직접 "나 잘 지내"라고 말하지 않아도 기록이 대신 전달

## 잠재적 기술 리스크

| 리스크 | 영향 | 대응 방안 |
|---|---|---|
| 연락처 연동 — iOS Safari Contacts Picker API 미지원 | 중 | iOS는 카카오 친구 API로 대응; Android Chrome은 Contacts Picker API 추가 지원; React Native 앱 출시 후 JS Bridge로 전 환경 네이티브 연락처 접근 가능 |
| 가족 연결 — 비회원 자녀 조회 링크 | 중 | 초기에는 자녀도 Bloom 가입 필요. 비회원 읽기 전용 링크는 2단계 |
| 리액션 팝오버 — 존재를 모르고 지나칠 수 있음 | 낮음 | 상세 화면에서 5개 버튼 항상 노출; 피드 카드에도 "반응 더보기" 레이블 텍스트로 명시 |
| 월간 리포트 집계 쿼리 성능 | 낮음 | 월 1회 생성, Redis 캐시 또는 스케줄 배치 고려 |
